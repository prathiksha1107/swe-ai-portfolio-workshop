# Instructions for Personalizing My Portfolio

1. Read `PROFILE.md` completely before editing anything.
2. Personalize the portfolio using only information provided in `PROFILE.md`.
3. Do not invent employers, accomplishments, numbers, technologies, education,
   awards, certifications, publications, or project results.
4. If important information is missing, leave it out rather than inventing it.
5. Preserve the overall Minimal Professional layout and understated visual style.
6. Preserve semantic HTML, heading order, keyboard navigation, visible focus styles,
   ARIA attributes, the skip link, contrast, and responsive behavior.
7. Do not modify `script.js` unless necessary for functionality.
8. Do not introduce React, Angular, Node, npm, Tailwind, frameworks, build tools,
   APIs, external dependencies, environment variables, or databases.
9. Keep every path relative and keep the project compatible with GitHub Pages.
10. Use concise, honest, recruiter-friendly writing.
11. Present every project using Problem, Approach, Impact, and Technologies. Problem
    says what needed solving; Approach says what the person did; Impact says what
    changed or was learned; Technologies names the actual tools or methods used.
12. Remove sections with no meaningful information instead of adding fake content.
13. Remove a link when no real URL was provided.
14. Verify all remaining links and asset references.
15. Verify desktop and mobile layouts and check keyboard navigation.
16. Do not change the design dramatically unless the user explicitly requests it.
