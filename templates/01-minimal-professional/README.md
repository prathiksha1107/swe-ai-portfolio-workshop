# Minimal Professional

Status: Stable  
Template ID: 01-minimal-professional  
Workshop Ready: Yes

## Best for

Software engineers, data professionals, AI engineers, technical professionals, and
participants who want a clean, recruiter-friendly portfolio.

## Required workflow

**Resume → Skill 01 → PROFILE.md → Human Approval → Skill 02 → Portfolio → Human
Review → Skill 03**

1. Use `skills/01-resume-to-profile/SKILL.md` to extract resume facts into
   `PROFILE.md`.
2. Review every field. When it is accurate and safe for public use, set the Human
   Review status to `APPROVED FOR PORTFOLIO GENERATION`.
3. Use `skills/02-profile-to-portfolio/SKILL.md` to personalize this existing site.
4. Visually review the generated portfolio.
5. Use `skills/03-portfolio-qa-deploy/SKILL.md` for QA. Deployment always requires a
   later, explicit approval.
6. After the site is live, optionally follow the
   [free analytics guide](../../guides/04-add-free-analytics.md) to add a
   participant-owned Microsoft Clarity project.

## Files participants normally interact with

- `PROFILE.md` is the structured content contract. Participants normally update it
  through the AI workflow rather than manually editing website code.
- `assets/` stores a participant's optional public `resume.pdf` and any approved
  images.
- `index.html` contains the page structure and content generated by Skill 02.
- `style.css` contains the final Minimal Professional design.
- `script.js` handles the accessible mobile menu and current footer year.

No npm, framework, build process, API, database, or local server is required. To
preview the starter or personalized site, double-click `index.html` and refresh the
browser after changes.

## Design rule

The design is final. Skills may personalize, remove, or reorganize content only as
needed to fit approved profile information. They must preserve the colors,
typography, spacing, layout conventions, responsive behavior, accessibility, and
component styles.

## Contact options

Skill 02 displays only contact methods explicitly configured in `PROFILE.md`:

- Public email, LinkedIn, and GitHub are shown when their values are present.
- A static contact form appears only when enabled and supplied with an approved
  public endpoint.
- WhatsApp appears only when explicitly enabled with an approved international
  number.

Contact forms and WhatsApp are disabled by default. Missing or disabled options are
omitted—never replaced with empty buttons, fake URLs, phone numbers, endpoints, or
credentials.

## Resume handling

The optional public resume belongs at `assets/resume.pdf`. It is connected only when
the participant approves the download and the file exists. This starter does not
include or link to anyone else's resume.

## Completed example

Personalized examples are preserved under `examples/01-minimal-professional/`. They
reuse this template's final CSS and JavaScript while keeping personal information
outside the starter.

## Optional visitor analytics

The starter intentionally contains no tracking ID. After deployment, participants
may create their own free Microsoft Clarity project and ask an AI assistant to add
the supplied tracking code at the marked `ANALYTICS` location in `index.html`.
Follow the [free analytics guide](../../guides/04-add-free-analytics.md). Never copy
an ID from an example site.
